# Этап 12 — Saby: контакты и наличие грузового транспорта

**Только тестовая ветка:** `feature/saby-stage12-transport-windows-20261109`.
`main` и действующий VPS не изменяются.

## Что меняется

1. Этап 12 запускается после этапа 11 и финальной deterministic QA.
2. В Excel название заголовка `TORGBOX` (его существующая колонка) меняется на **«Наличие транспорта»**. Структура, расположение листов, оформление, формулы и остальные колонки сохраняются.
3. В этой колонке сохраняются **только грузовые автомобили Saby** с пометкой `Saby (грузовые):`. Подтверждённая информация о прицепах TORGBOX сохраняется отдельной строкой, не выдаётся за грузовые автомобили и не удаляется.
4. Телефон добавляется **только если он отсутствует** в итоговой строке и не закреплён за другим ИНН. Email сохраняется в примечании и в `__evidence.saby`. Квалификация A/B/C и исходные источники не меняются.
5. Совпадение ИНН и юридического названия обязательно. Дубликаты ИНН, неполные/обрезанные списки техники и неоднозначные результаты Saby уходят на ручную проверку. Контакты сохраняются, даже если автопарк не извлечён.
6. Браузер Saby использует отдельный авторизованный профиль Playwright. **Никакие cookies или ключи Google Sheets не переносятся в репозиторий.**
7. Этап **отключён по умолчанию** (`SABY_STAGE12_ENABLED=false`), чтобы не запускать браузер Saby на действующем VPS при следующих обновлениях.

## Как безопасно протестировать на Windows

Рекомендуется отдельная папка, а не изменение локального `main`:

```powershell
git clone --branch feature/saby-stage12-transport-windows-20261109 https://github.com/AlexK0l/RegionalResearch.git RegionalResearch-SabyTest
cd RegionalResearch-SabyTest
npm ci
npx playwright install chromium
py -m pip install openpyxl==3.1.5
npm test
```

Для экспорта в строгом формате скопируйте в `data/SAT_reference_template.xlsx` **обезличенный** шаблон из вашего работающего проекта. Не добавляйте его или `.env` в Git.

### Шаг А. Добавить логин и пароль в локальный .env

Если .env ещё нет, создайте его в корне тестовой копии проекта:

```powershell
Copy-Item .env.example .env
```

В существующий локальный `.env` добавьте или заполните **две строки**:

```dotenv
SABY_LOGIN="ваш_логин_или_телефон"
SABY_PASSWORD="ваш_пароль"
```

Обе переменные обязательны для автоматического входа. Не вводите значения в чат,
логи, команды PowerShell или GitHub. `.env` исключён из Git. Если в пароле есть
`#` или пробелы, сохраняйте кавычки: так Node.js корректно прочитает строку.
Значения можно оставить пустыми для прежнего ручного входа.

Проверьте автологин отдельно от исследования:

```powershell
npm run saby:smoke -- --login
```

Команда теперь автоматически читает `.env`, проверяет уже сохранённую сессию
`data/saby-profile`, а при необходимости вводит логин и пароль **только** на
`https://online.saby.ru/auth/`. Если Saby запрашивает SMS, одноразовый код,
CAPTCHA или иной дополнительный фактор, завершите вход вручную в открытом
браузере. Скрипт сам проверит сессию и завершится без нажатия Enter.
Если Saby остаётся на странице подтверждения, она будет доступна для ручного
действия во время проверки. Скрипт не обходит CAPTCHA и двухфакторную защиту.

После успешного входа профиль сохраняется локально на Windows, пароль повторно
не вводится до истечения/сброса сессии. Не передавайте каталог профиля третьим
лицам.

### Если вход автоматически не прошёл

Обновите тестовую ветку:

```powershell
git pull origin feature/saby-stage12-transport-windows-20261109
npm run saby:smoke -- --login
```

Новая реализация учитывает оба официальных маршрута SSO:
`https://online.saby.ru/auth/` и `https://sso.sbis.ru/auth-online/`
(также `sso.saby.ru/auth-online/`). Сохраняет исходный адрес возврата в
Saby Profile, ожидает загрузки полей и поддерживает переход по кнопке-стрелке.

Новый тест автоматически ждёт подтверждения сессии в браузере. Если
поля логина и пароля отправлены, но обновлённый интерфейс Saby не показывает
старое поле поиска, дополнительно проверяется сама страница списка компаний.
Никакой команды Enter для сохранения сессии больше не нужно.

В PowerShell появятся безопасные метки `[SABY_AUTH] start`,
`login_field_found`, `login_filled`, `login_advanced_...`,
`password_field_found`, `submitted`, `authenticated`
или `manual_required`. Они не содержат учётных данных.

Если ошибка повторится, передайте **только метки `[SABY_AUTH]` и текст
сообщения**, без содержимого `.env`, пароля, cookies и скриншотов
с введёнными учётными данными. Если Saby показывает CAPTCHA, одноразовый
код или push-подтверждение, выполните его вручную: программа их не обходит.

Если в Saby нужен именно установленный Google Chrome, используйте
`$env:SABY_BROWSER_CHANNEL='chrome'` перед запуском. Настоятельно не рекомендуется копировать профиль из присланного архива: у него могут быть истёкшие или привязанные к компьютеру cookies.

### Шаг Б. Бесплатный тест по одному ИНН

```powershell
npm run saby:smoke -- "--inn=7707083893" "--name=ПАО Сбербанк" --limit=1 --xlsx
```

Это **технический пример**. Для проверки извлечения транспорта выберите вместо него компанию из вашей базы с известным подтверждённым ИНН и грузовым автопарком.

Скрипт создаст новый JSON и XLSX в `data/`, **не изменяя** исходные файлы, SQLite, Google Sheets или основной сайт. Он не использует OpenAI API.

### Если после входа не найдено поле поиска

Скрипт теперь сначала проверяет обычные поля поиска, а затем — **единственное
доступное текстовое поле**, как в исходном `saby_agent.py`. После открытия
каталога ждёт загрузку Saby Profile до 15 секунд. Не вводит ИНН в поля логина,
пароля или SMS и не угадывает поле, если видимых текстовых полей несколько.

```powershell
git pull origin feature/saby-stage12-transport-windows-20261109
npm run saby:smoke -- "--inn=6027087063" "--name=ООО «Дорстройсервис»" --limit=1
```

Успешно обнаруженный поиск отмечается в PowerShell одной безопасной строкой:
`[SABY_SEARCH] search_selector` или
`[SABY_SEARCH] single_visible_input`.

Если поле по-прежнему не найдено, появится
`[SABY_SEARCH_DIAG] {"code":"...",...}`. Присылайте **только текст
диагностики и ошибку**, без сессии Chrome, содержимого `.env` или снимков
экранов с контактами. Значения из полей ввода, cookies и текст страницы эта
диагностика не собирает.

### Шаг В. Тест на сохранённом исследовании без платного запуска

```powershell
npm run saby:smoke -- "--result=SAT_Смоленская_область.json" --limit=3 --xlsx
```

Исходный JSON должен содержать `final_result` или секции `direct_buyers`, `intermediaries`, `leasing`. Тест просматривает максимум три компании, создаёт **новый** JSON и XLSX в `data/`. Если карточку Saby подтвердить нельзя, строка остаётся неизменной и фиксируется `review`.

## Включить этап 12 в полном локальном исследовании

После успешных бесплатных тестов добавьте **только в локальный** `.env`:

```dotenv
SABY_STAGE12_ENABLED=true
SABY_LOGIN="ваш_логин_или_телефон"
SABY_PASSWORD="ваш_пароль"
SABY_PROFILE_DIR=./data/saby-profile
SABY_HEADLESS=false
SABY_MAX_COMPANIES=3
STAGE12_MAX_MS=1800000
SABY_COMPANY_TIMEOUT_MS=45000
SABY_DELAY_MS=1500
```

`SABY_MAX_COMPANIES=3` ограничивает работу на начальном тесте; `0` разрешает весь список до временного ограничения. Для больших исследований этап может быть ограничен доступностью Saby; непроверенные ИНН остаются в checkpoint для продолжения. Используйте подтверждённую авторизованную сессию и не обходите капчи/ограничения Saby.

**Важно:** полный запуск этапов 1–11 по-прежнему расходует OpenAI API и `web_search`. Чтобы бесплатно проверить только Saby, используйте исключительно `npm run saby:smoke`.

## Контроль качества

- `npm test`: статические и offline-регрессионные проверки без платных API.
- `npm run smoke:xlsx`: проверка оформления с тестовыми данными.
- В `saby_stage12`: `verified`, `review`, `phonesAdded`, `transportsAdded`, `deferred`.
- В `__evidence.saby`: подтверждённый ИНН, URL карточки, дата, отдельно контакты и типизированный грузовой парк.
- Обратите внимание на `review`: Saby иногда меняет DOM. Настоящий UI-интеграционный тест возможен только на Windows с действующей сессией пользователя.

## Безопасность

Не добавляйте в GitHub и не прикладывайте к публичным отчётам: `.env`, `data/saby-profile`, `service-account.json`, cookies Chrome, диагностические скриншоты с телефонами/персональными данными. После старого архива, содержащего сервисный ключ и браузерный профиль, проверьте необходимость ротации ключа.
