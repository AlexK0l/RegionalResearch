# Этап 12 Saby: интеграция и безопасный выпуск

## Подтверждено

- На Windows: авторизация и постоянная сессия, поиск и подтверждение
  карточки по ИНН, извлечение телефонов, email и грузовых автомобилей,
  пакетный smoke-test по ранее сохранённой Смоленской области.
- GitHub Actions на Windows и Ubuntu: офлайн-регрессии Saby, бизнес-правил
  и строгого XLSX (полный набор тестов проекта).
- Офлайн-интеграционный тест запускает тот же модуль, что основной
  конвейер. Проверяется checkpoint этапа 12, сохранение/чтение через SQLite,
  восстановление только незавершённых ИНН, отсутствие перезаписи старых
  контактов/TORGBOX и формирование 5-листного XLSX.
- При симуляции отсутствующего Chromium сведения не изменяются,
  необработанные ИНН откладываются, а Excel формируется штатно.

**На Time4VPS проверено 10 ноября 2026:** в Linux Saby успешно извлекает
контакты и полный грузовой автопарк и в обычном headless-shell, и в новом
headless Chromium, и в headed Chromium с Xvfb, в том числе на чистом профиле.
Основной Saby-only smoke без DISPLAY, OpenAI и записи в SQLite прошёл:
checked=1, contactUpdates=1, transportUpdates=1, review=0.
Один предшествующий неудачный headless-запуск не воспроизвёлся;
для отсутствующих одновременно двух разделов предусмотрено однократное
повторное открытие карточки, затем review/deferred без записи ложных данных.
**Рекомендуемый режим на VPS — SABY_HEADLESS=true**; Xvfb оставлен как
необязательная альтернатива для ручной диагностики.
Отдельно тестируется строгое сопоставление компаний, у которых Saby
показывает сокращённое название: точный ИНН в выдаче не заменяет
проверку полного наименования по регистрационным реквизитам.

## Неизменный контракт XLSX

- Те же 5 листов, порядок, набор колонок, ширины, стили, формулы,
  условное форматирование и существующие примечания эталона.
- Единственное заранее согласованное переименование: заголовок
  третьей колонки с TORGBOX на «Наличие транспорта».
- «Телефон» — только номера и, при прямом подтверждении, отдел в скобках.
  Никаких имён источников, ссылок, email или свободных пояснений.
- Грузовые машины Saby и прицепы TORGBOX сохраняются отдельно;
  подробности транспорта — в уже существующих данных evidence.

## Безопасный выпуск на Time4VPS

1. Сначала завершить все активные исследования, скачать результаты,
   проверить актуальность резервной копии SQLite и файлов.
2. После слияния обновить main по процедуре из
   deploy/time4vps/README.md, не повторяя первоначальный install.sh.
   Оставить переменную SABY_STAGE12_ENABLED=false.
   Это позволит развернуть новую версию без запуска Saby.
3. Для последующего включения Saby поставить системные зависимости
   Chromium от root и сам браузер от пользователя regionalresearch:

       sudo /opt/regionalresearch/node_modules/.bin/playwright install-deps chromium
       sudo -u regionalresearch env HOME=/var/lib/regionalresearch \
         /opt/regionalresearch/node_modules/.bin/playwright install chromium

   Убедиться, что браузерный профиль в
   /opt/regionalresearch/data/saby-profile доступен для записи этому
   пользователю. Не загружать профили и секреты в GitHub.
4. На проверенном VPS используйте **SABY_HEADLESS=true** без DISPLAY.
   Browser storage уже проверен в
   /home/regionalresearch/.cache/ms-playwright; при HOME=/var/lib/regionalresearch
   задайте systemd drop-in PLAYWRIGHT_BROWSERS_PATH с этим каталогом.
   Опциональный Xvfb для диагностики описан в
   [SABY_VPS_HEADED.md](SABY_VPS_HEADED.md).
5. Проверить один ИНН локальной командой npm run saby:smoke с
   аргументами --inn, --name и --limit=1. Это не запускает OpenAI
   и не меняет исходные исследовательские JSON; обращение к Saby есть.
6. Только после проверки установить на VPS
   SABY_STAGE12_ENABLED=true и начальный SABY_MAX_COMPANIES=1.
   Планово перезапустить службу после завершения текущих заданий.
   Повышать лимит постепенно, наблюдая за памятью и review.
7. Один постоянный браузерный профиль не открывать одновременно
   в разных процессах. Проект сериализует Saby-задания внутри одного
   Node-процесса.

## Откат

Установить SABY_STAGE12_ENABLED=false и планово перезапустить службу
после завершения исследований. SQLite, WAL/SHM, .env, профили Saby
и исходные данные не удалять. Базовые этапы исследования остаются
доступны без включённого Saby.
