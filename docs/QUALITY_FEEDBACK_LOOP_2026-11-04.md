# Замкнутый цикл качества исследования (04.11.2026)

## Зачем изменён код

Предыдущие разборы Excel исправляли сохранённый результат, но **не исправляли платный процесс поиска**. Изменения этой ветки устраняют дефекты прямо в `src/pipeline.js`, до повторного платного обогащения.

## Что теперь делает живой конвейер

1. **Discovery** сохраняет ИНН из уже найденных источников только у названного юридического лица, отдельно описывает лизингодателя, лизингополучателя, владельца и фактического перевозчика, а также проверяет принадлежность упоминания нужному субъекту РФ. Отдельный платный поиск ИНН в discovery не вводится.
2. **Identity** считает кластер поисковым пакетом, а не подтверждённым юридическим лицом. Соседнее упоминание не наследует ИНН без своего доказательства. В ответе модели требуется связка `legal_name`, `confirmed_inn` и конкретный URL для **каждой** карточки. При несовпадении названий или ИНН сохраняется гипотеза, а не подменяются поля компании.
3. **Deduplication** сохраняет доказательства, полные исходные снимки и ID только у подтверждённых алиасов. Два разных юридических лица с одинаковым ИНН без подтверждения не получают общий ID.
4. **Final INN** пустой результат поиска не стирает ранее найденный ИНН, противоречащий результат не заменяет его молча. Для новой записи требуется URL-источник. В первой попытке сохраняется широкая проверка отсутствующих ИНН. Второй платный запрос по пропуску выполняется только при появлении **нового URL**, если не установлена `OPENAI_FINAL_INN_RETRY_WITHOUT_NEW_SOURCE=true`.
5. **Качество до оплаты**: перед платным enrichment/поиском контактов вызывается `finalizeProductionResearch`; неподходящие и конфликтующие карточки помещаются в REVIEW, не удаляются. В конце контактного этапа проверка повторяется для новых доказательств.
6. **Измерение**: `scripts/compare-research-runs-offline.js` сравнивает два сохранённых запуска по действительным ИНН и не принимает перенесённые из REVIEW записи за новые открытия.

## Офлайн-проверка (Смоленск)

Воспроизведён архив `SAT_Smolensk_verified_identity_recovery_2026-11-04.json` с 446 коммерческими записями, 238 REVIEW, 83 EXCLUDED и 16 архивными снимками. Прямая проверка:

- 767/767 действующих ID и защищённые поля сохранены без изменений.
- 387 уже заполненных ИНН проверены на пустой ответ позднего поиска: **0 потерь**.
- 387 конфликтных ответов проверены на самовольную перезапись: **0 замен**, все фиксируются как спорные.
- `finalizeProductionResearch` повторно сохранил **446 коммерческих**: не отправил в REVIEW восемь ранее разрешённых исторических алиасов.
- Из 59 отсутствующих коммерческих ИНН **0** имели новый URL для автоматического второго поиска в сохранённом снимке. На новом платном прогоне число повторов может отличаться.
- Эта проверка **не подтверждает** независимую актуальность источников класса A и **не измеряет** стоимость настоящего будущего исследования.

## Использование на Windows, не изменяя текущий локальный main

В Git Bash или PowerShell с установленным Git запустить из текущего клона:

```powershell
git fetch origin
git worktree add --detach ..\RegionalResearch-feature origin/feature/evidence-first-cost-quality-20261028
cd ..\RegionalResearch-feature
npm ci
```

Только после переноса своего локального `.env` (без публикации в репозитории) запускать `npm run local`. Проверить, что порт 10000 свободен: не запускать старую и новую версии одновременно. SQLite старой программы не подключать к новому экземпляру без резервной копии. **Никакой автоматической миграции базы или слияния веток этот runbook не выполняет.**

## Сравнение до и после реального запуска

```powershell
node scripts/compare-research-runs-offline.js OLD.json NEW.json --out=run-comparison.json
node scripts/audit-final-result-readonly.js NEW.json --out=qa-new.json --fail-on-critical
npm test
```

Ключевые показатели: новые подтверждённые юридические лица (ИНН, отсутствовавшие в **любой** исходной очереди), сохранённые ранее подтверждённые ИНН, доля A с источником, число спорных юридических идентификаций, число платных web/search вызовов и фактический API cost **из логов**. Если прирост не соответствует расходам, не продолжать полный платный поиск лишь ради роста количества A/B/C.

## Ограничения и контроль развёртывания

- `main` не содержит этих исправлений, пока изменения не объединены. CI экспериментальной ветки не означает, что пользовательский Windows-клон уже обновлён.
- Корректный контрольный разряд ИНН + URL не доказывают совпадение конкретного юрлица с этим номером. Для спорных юридических лиц необходим реестровый документ.
- Качество следующего **платного** discovery нельзя доказать только офлайн-регрессией. Сначала испытать ограниченный тестовый запуск с бюджетом и сравнением по scorecard.
- Повторно проверять 200+ уже отложенных карточек без новых источников нецелесообразно; прогресс измеряется улучшением следующего запуска.
