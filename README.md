# RegionalResearch

Веб-приложение для регионального поиска потенциальных покупателей CAT.

## Как работает

1. Пользователь выбирает регион.
2. Шаги 1–9 выполняют последовательный поиск через OpenAI Responses API с web_search.
3. Шаг 10 объединяет результаты и выполняет дедупликацию.
4. Шаг 11 открывает Chromium через Playwright и пытается найти публичные контакты компаний через интерфейс Google AI Mode.
5. После завершения формируется итоговый XLSX.

## Структура

- `server.js` — Express Web Service и API заданий.
- `src/` — исследовательский pipeline, Google AI Mode и генерация XLSX.
- `prompts/` — инструкции шагов 1–10.
- `public/` — пользовательский интерфейс.
- `render.yaml` — конфигурация Render.

## Локальный запуск

```bash
npm install
npx playwright install chromium
OPENAI_API_KEY=... npm start
```

По умолчанию приложение слушает `PORT` или порт `10000`.

## Render

Основная ветка: `main`.

Build command:

```bash
npm install && npx playwright install chromium
```

Start command:

```bash
node server.js
```

Переменные окружения:

```env
OPENAI_API_KEY=...
OPENAI_MAX_OUTPUT_TOKENS=128000
OPENAI_FINAL_BATCH_SIZE=60
OPENAI_RESEARCH_SOFT_TARGET=100
OPENAI_RESEARCH_MAX_RECOVERY_BRANCHES=3
OPENAI_RESEARCH_LOW_YIELD_THRESHOLD=3
FINAL_BATCH_MODEL=gpt-5.6-luna
TARGETED_SEARCH_MODEL=gpt-5.6-luna
FINAL_QA_MODEL=gpt-5.6-luna
CONFLICT_MODEL=gpt-5.6-sol
COMPUTER_MODEL=gpt-5.6-luna
COMPUTER_FALLBACK_MODEL=gpt-5.6-sol
GOOGLE_AI_MAX_TURNS=6
GOOGLE_AI_VIEWPORT_WIDTH=1024
GOOGLE_AI_VIEWPORT_HEIGHT=768
GOOGLE_AI_SCREENSHOT_DETAIL=low
GOOGLE_AI_SOL_RETRY_PRIORITY_AB=true
```

Шаги 1–9 ограничиваются 50 000 output tokens и сохраняют скрытый evidence (URL, официальный сайт, email и найденные подтверждения). Шаг 10 сначала программно строит canonical-компании, затем обрабатывает их пакетами по 60 на GPT-5.6 Luna БЕЗ web_search. Если после этого у конкретной компании остаются пробелы в примечании/ИНН, выполняется один точечный web_search только по этой компании на Luna. Конфликтные дубли отдельно передаются GPT-5.6 Sol без web_search. Глобальный QA выполняется Luna без поиска; региональная статистика собирается отдельным search-вызовом.

Google API не используется. Google AI Mode запускается только для компаний, где после основного исследования отсутствует подтверждённый телефон или ЛПР. Одна Chromium-сессия переиспользуется между компаниями. Основная computer-use модель — GPT-5.6 Luna; GPT-5.6 Sol используется как fallback при технической недоступности/неудаче Luna. Лимит computer-use — 6 ходов, viewport 1024×768, screenshot detail — low. Если Google показывает CAPTCHA, требует вход или не предоставляет AI Mode, приложение не пытается обходить защиту.


Для компаний уровня A/B, если Luna в Google AI Mode завершила поиск со статусом `not_found`, выполняется одна дополнительная попытка через GPT-5.6 Sol. Для C-компаний этот повтор не выполняется, чтобы сохранить экономию.


### Полнота этапов 1–9

Этапы больше не выполняются тремя общими проходами. Каждый этап имеет обязательный набор тематических поисковых веток, сформированный из исходных пользовательских инструкций. Каждая ветка делает серию web-search запросов по своей теме, проходит географию региона и передаёт следующей ветке список уже найденных организаций, чтобы искать long tail вместо повторов.

После всех обязательных веток, если уникальных релевантных организаций меньше мягкого ориентира `OPENAI_RESEARCH_SOFT_TARGET` (по умолчанию 100), запускается до трёх дополнительных веток: географические пробелы, альтернативные источники/синонимы и цепочки второго порядка. Добор прекращается раньше только после двух подряд низкорезультативных веток. 100 — ориентир полноты, а не квота: выдумывать компании запрещено.

Шаг 10 не компенсирует слабый discovery массовым поиском. Программное canonical-объединение выполняется только по одинаковому подтверждённому ИНН. Возможные дубли без ИНН не схлопываются по одному названию/городу и разбираются глобальным QA по совокупности признаков.


### Судебный архив для этапа 7

В проект встроен компактный индекс пользовательского архива из 10 109 markdown-документов судебных актов. Индекс содержит названия судов и организаций, упомянутых в документах, и используется только на этапе 7 как дополнительный источник discovery по выбранному региону. Найденные по архиву организации затем проверяются через web_search/официальные судебные источники; одно упоминание в архиве не считается достаточным доказательством владения или эксплуатации техники.
